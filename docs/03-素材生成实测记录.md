## 二、踩过的 5 个错（按遇到顺序）

### 1. `404 InvalidEndpointOrModel.NotFound` —— 模型 ID 不存在

```
The model or endpoint doubao-seedream-4-0-250828 does not exist or you do not have access to it.
```

**原因**：脚本里的默认 ID 是带日期的**占位值**，而这个 ID 在目录里的状态已经是 `Retiring`。
**花费 ¥0**（生成前就被拒）。**修法**：换成"不带 status 字段"的当前可用 ID。

### 2. `404 ModelNotOpen` —— ID 对了，但账号没开通

```
Your account 2114452012 has not activated the model doubao-seedream-5-0-pro-260628.
Please activate the model service in the Ark Console.
```

**原因**：方舟的模型要先在控制台「**开通管理**」里点开通（开通免费，按量计费）。
**花费 ¥0**。**修法**：去控制台开通。

> 这两个 404 的区别很重要：`InvalidEndpointOrModel` 是 ID 错，`ModelNotOpen` 是权限/开通，
> 报错文案完全不同，别混。

### 3. `400 InvalidParameter.TaskTypeConstraint` —— 带首帧时不能传 `ratio`

```
The parameter ratio specified in the request is not valid.
For first-frame or first-last-frame generation, the output ratio follows the first-frame image.
```

**原因**：**图生视频时输出比例自动跟随首帧图**，再传 `ratio` 反而非法。
**花费 ¥0**。**修法**：`buildVideoBody()` 里，只要有首帧就不发 `ratio`。

### 4. `400 InvalidParameter` —— seedance-2-5 的 i2v 不接受 `camera_fixed`

```
the specified parameter camera_fixed is not supported for model doubao-seedance-2-5 in i2v, must be empty
```

**原因**：不同代模型支持的可选参数不同。`camera_fixed`（固定镜头）在新模型的图生视频里不被接受。
**花费 ¥0**。**修法**：一律不发 `camera_fixed` —— 反正**提示词里已经用自然语言写死了**
「镜头完全固定：不推拉、不旋转、不缩放、不移动」，效果一样。

### 5. 图片格式不是 PNG —— 硬按 `.png` 存会让 MIME 出错

Ark 的图生图即使 `response_format=b64_json`，返回的也可能是 **JPEG**（响应里
`data[0].output_format` 会写出来）。旧代码硬写 `.png` 后缀 + `data:image/png` 前缀，
后果：① 文件后缀与字节不符；② 拿它当视频首帧时 MIME 是错的。
**修法**：新增 `sniffImage(buf, declared)`，按 `output_format` / 魔数判定，落盘与 data URI 都用真实格式。

## 三、怎么零成本列出可用的模型 ID

Ark 是 OpenAI 兼容端点，有 `/models`：

```powershell
$env:ARK_API_KEY = "你的key"
curl.exe -s -H "Authorization: Bearer $env:ARK_API_KEY" `
  "https://ark.cn-beijing.volces.com/api/v3/models"
```

**挑选规则（实测）**：条目里带 `status: "Shutdown"` 或 `"Retiring"` 的是已下线/正在下线，
**调用必然 404**；**不带 `status` 字段**的才是当前可用。

> ⚠ **`400 InvalidParameter` 不能用来判断模型是否存在**。我们做过对照实验：
> 一个完全不存在的假模型名，同样返回 `400 InvalidParameter` —— 因为参数校验跑在模型校验**之前**。
> 所以"发个错请求看是 400 还是 404"这个办法**是无效的**，别用。

## 四、计费：按 token 算，公式可以精确预测

### token 公式

```
tokens ≈ (宽 × 高 × 帧率 × 时长) ÷ 1024
```

实测校验：720p（1280×720）/ 24fps / 5 秒 → 公式给 **108,000**，真实任务 `usage.total_tokens` = **108,900**
（误差 0.8%）。所以分辨率和时长**都**直接影响费用。

### 单价（火山引擎文档《AICC-Seedance2.0模型计费说明》2026-08-03 版）

| 模型规格 | 类型 | 元/百万 tokens |
|---|---|---|
| doubao-seedance-2.0（**480P / 720P**） | 不含视频输入 | **92** |
| doubao-seedance-2.0（480P / 720P） | 含视频输入 | 56 |
| doubao-seedance-2.0（1080P） | 不含视频输入 | 102 |

> ⚠ 我们用的是 **seedance-2-5**，单价可能高于 2.0。**以控制台账单为准。**
> ⚠ **480P 与 720P 单价相同** —— 省钱只能靠降分辨率（token 少），不是换个便宜型号。

### 由此推出的价目（92 元/百万 tokens、24fps）

| 方案 | tokens/段 | ¥/段 | 10 段合计 |
|---|---|---|---|
| 720p / 10 秒 | 216,000 | ¥19.9 | **¥199** ❌ |
| 720p / 5 秒 | 108,000 | ¥9.9 | ¥99 |
| 480p / 10 秒 | 96,000 | ¥8.8 | ¥88 |
| **480p / 5 秒** | **48,000** | **¥4.4** | **¥44** ✅ |

**结论：用 `--resolution 480p --duration 5`。**
素材最终要被 `keyscreen.mjs` 缩到 **640×360**，480p（864×480）完全够，效果几乎无差别，
而比默认的 720p/10 秒省 **78%**。

```powershell
# ③ 抠像 → 装进插件 → 体检

# ④ 确认无误再全量（约 ¥44；必须显式加 --all）
node tools\gen-api.mjs --all --resolution 480p --duration 5 --go

```

### 省钱与防重复扣费的几个机制

| 机制 | 说明 |
|---|---|
| 断点续跑 | `out/raw/<动作名>.mp4` 已存在就跳过（0 请求 0 花费），静帧在还会复用（省一次图片调用） |
| 失败不重发 | 模型报错 / 任务 `failed` / 审核拒绝 → 立刻停并非 0 退出；**只有 429 才重试 POST**（5xx 与网络错误对 POST 不重试，因为无法区分"没收到"和"收到了并计费"） |
| 并发默认 1 | 一段失败时，"已经在飞"的段仍会把花钱的 POST 发出去；并发越低，失败瞬间多花的钱越少 |
| `--force` vs `--force-still` | `--force` 只重做视频，不牵连静帧；`--force-still` 才重出图 |
| probe 复用静帧 | 反复重探不会重复买图 |

## 七、⚠ 怎么测「花钱闸门」—— 一条血的教训

**2026-10-05 我犯的错**：给脚本加完预算闸门后，我用**带 `--go` 的真实命令**去验证它：

```powershell
node tools\gen-api.mjs --all --resolution 480p --duration 5 --go   # 预估 ¥42 < 闸门 ¥50 → 放行 → 真的开始生成
```

这不是测试，这是**真实调用、真实花钱**。2 分钟后我 kill 掉它，**并发默认 1 救了场**：
只建了 1 个视频任务（不是 9 个），损失 **¥4.66**（1 张图 ¥0.2 + 1 段 480p/5s ¥4.46）。
那个任务在服务端跑完了，我把它收下来加工成了正式的 `东张西望.webm` —— 钱没白花，
但**这是运气，不是流程**。

### 正确做法：`--self-test`（假 fetch，零网络零花费）

```powershell
node tools\gen-api.mjs --self-test
```

它给每个用例**另起一个子进程**并强制 `GENAPI_STUB_FETCH=1`，子进程里的
`globalThis.fetch` 被换成假的（调用只写进日志文件），所以**哪怕用例带 `--go` 也发不出一个真实请求**。
断言两件事：

| 用例 | 断言 |
|---|---|
| 不给 `--go` | 退出码 0，**0 次网络调用** |
| 给 `--go` 但没给 `--all`/`--limit`/`--only` | 退出码 1，**0 次网络调用** |
| 超预算闸门（默认 720p/10 秒全量 ¥180） | 退出码 1，**0 次网络调用** |
| 真跑路径（走假 fetch） | 出图 → 建任务 → 轮询 → 下载；且请求体**不得含 `camera_fixed`**、**带首帧不得含 `ratio`**、**必须显式 `generate_audio:false`** |

最后一条就是上面那些踩坑的**回归测试** —— 以后再改返回体，改错会立刻被这个自测抓住。

> 改过闸门或请求参数后，**先跑 `--self-test`**。永远不要用带 `--go` 的真命令去测闸门。
